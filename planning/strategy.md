# Cloumy 제품·비즈니스 전략

> 이 문서는 제품 방향과 비즈니스 결정의 단일 진실 공급원(Single Source of Truth)이다.
> 기술 상세는 `feature-*.md`, 구현 계획은 `milestones.md`, 우선순위는 `priorities.md` 참고.
>
> ⚠️ **2026-07-06 타겟 전환**: 한국인 국내 여행자 → **방한 외국인 관광객(미국·일본·중국·대만)**. 기존에 이 문서가 담고 있던 "국내 MVP → 한국인 해외 아웃바운드 피벗" 로드맵은 전량 폐기하고, 방한 인바운드 기준으로 재작성함. 근거: Cloumy Notion 기획 문서(서비스 개요/타겟 페르소나/MVP 범위/로드맵&KPI).

---

## 핵심 비전

**"AI가 완성된 여행 루트를 짜주고, 여행 중에도 함께한다."**

방한 외국인 관광객이 언어·정보 장벽 없이 한국을 깊이 경험할 수 있도록, 목적지·날짜·취향만 입력하면 AI가 최적 동선·예산·팁이 담긴 완성 루트를 생성하고, 여행 중에는 다국어 챗봇이 실시간으로 대안 추천·예산 추적·현지 정보(메뉴판·키오스크 번역 등)를 제공한다.

장기적으로는 재한 외국인·K-culture 마이크로 인플루언서 등 루트 크리에이터 생태계(UGC)를 통해 검증된 "외국인 친화" 현지 장소 데이터로 경쟁 우위를 확보한다.

## 경쟁 포지셔닝

### vs GOKO (핵심 경쟁자, 2026.06.26 출시)

| | GOKO | Cloumy |
|--|------|--------|
| 지원 플랫폼 | iOS 전용 | iOS + Android |
| 서비스 범위 | 루트 생성만 | 루트 생성 + 실행(챗봇·예산·내비) + 공유 |
| 여행 중 AI | 없음 | 다국어 챗봇 (텍스트+카메라) |
| 콘서트·이벤트 앵커 | 없음 | Serper+KOPIS 실시간 검색 |
| 외국인 친화 정보 | 없음 | Foreigner Friendly Score |
| 수익 모델 | 완전 무료 | Trip Pass (Standard/Extended) |

### vs KOIN(Korea Insider) / Creatrip

- KOIN: AI 카메라·큐레이션·커뮤니티에 집중 — Cloumy는 카메라 기능을 챗봇 안에 통합하고, 루트 플래닝→실행→공유 전 흐름으로 차별화
- Creatrip: 예약 커미션 기반 콘텐츠 커머스 — Cloumy는 AI 자동 루트 생성 + 실시간 실행 지원이 핵심 차별점

**포지셔닝**: 경쟁사는 "루트 정보/콘텐츠를 보여주는 도구", Cloumy는 "루트를 만들고, 여행 내내 옆에서 도와주는 실행 도구".

**1차 경쟁 목표**: GOKO의 "루트 생성만" 한계를 챗봇·예산·내비·공유로 넘어서는 것.

## 단계별 로드맵

### Phase 1 — 방한 외국인 MVP (현재, 0~6개월)

**목적**: 방한 외국인 관광객 대상 PMF 검증.

- **지역**: 코드상 이미 14개 도시 구현됨(서울·부산·제주·경주·강릉·전주·여수·인천·대전·대구·광주·속초·춘천·거제, `ai/app/config/city_centers.py`) — Notion MVP 목표 5개 도시(서울·부산·제주·경주·전주)를 이미 초과 달성한 상태
- **타겟**: 미국·일본·중국·대만 방한 관광객 (K-pop 팬, 재방문 여행자, 자유여행자, K-culture 복합 테마 여행자)
- **언어**: 챗봇은 영어·일본어·중국어(간체/번체) 지원, UI는 영어 우선 (일·중 UI는 Phase 1 후반)
- **데이터**: TourAPI + 카카오 로컬 + 네이버 지역검색 (국내 장소 DB, 기존 자산 그대로 활용)
- **성공 지표**: MAU보다 **여행 기간 내 DAU율 + Trip Pass 전환율** 우선

이 시장에서 이길 수 있는 모멘트:
1. 언어 장벽 + 정보 비대칭 → 현지 정보 접근 자체가 안 되는 문제를 챗봇으로 즉시 해결
2. 여행 중 실시간 돌발 대응 → "웨이팅 2시간, 대안 추천해줘" (GOKO 불가)
3. K-culture 목적형 여행 → K-pop 성지·K-drama 촬영지·콘서트 일정 기반 자동 루트

바이럴 루프: 루트 결과를 팬 커뮤니티(Reddit r/kpop 등)·SNS로 공유 → 신규 유입

### Phase 2 — 다국어 UI 확장 & 성장 (6~18개월)

**목적**: PMF 검증 후 스케일. 일본어·중국어 UI 전면 지원, 도시 커버리지 확대.

- **PMF 판단 기준**: Trip Pass 전환율 ≥3% + NPS ≥40 + "이 앱 없으면 불편" 응답 ≥40% 모두 충족 시 진행
- **추가 기능**: 일·중 UI 전면화, 행동 기반 태그 자동 보정, 더치페이 정산, 투어·숙박 예약 연동(Klook·Viator), AI 여행 일지, 오프라인 저장
- **도시**: 20개로 확대

### Phase 3 — 스케일업 & B2B (18~36개월)

- 전국 전 도시 커버 + 한국어 UI 추가(재한 외국인 장기 체류자 타겟)
- 크리에이터 수익 분배 프로그램
- B2B: 관광청·지자체 인사이트 리포트, 숙박·투어 예약 커미션, K-culture 브랜드 네이티브 광고
- 방일 외국인(인바운드) 등 해외 시장 적용 가능성 검토 (Phase 3 후반)

## 가격 전략

### Trip Pass 2단계 (금액 확정)

| 패스 | 대상 | 금액 |
|------|------|------|
| Standard | AI 루트 저장·편집, 챗봇, 예산 관리, 지도 내비, 루트 공유 | $4.99 |
| Extended | Standard 전체 + 오프라인 저장, AI 여행 일지 (Phase 2) | $7.99 |

**결제 수단**: ⚠️ 미확정 — 기존 계획이던 토스페이먼츠(국내 전용 PG)는 외국인 결제 수단(해외 카드 등)을 지원하지 않아 타겟과 맞지 않음. Stripe 등 국제결제 PG 검토 필요 (별도 논의 필요, 아직 결제 기능 자체가 미구현).

**Trip Pass 전환율 목표**: 5% (업계 평균 2.6% 상회, RevenueCat 2026 기준)

### 첫 여행 무료 (획득 전략)
- 신규 가입 후 첫 여행은 전 기능 무료 사용 → 재사용률 확보 후 전환

## 연기된 기능

### Hidden Gems — 모두의 창업 지원금 이후

- **연기 이유**: 1차 지원금 미확보 → GPS 인증 기반 커뮤니티 구축 비용 부담
- **DB 구조는 유지**: `places.rarity_score`, `places.is_hidden_gem`, `hidden_gems` 테이블 유지, 로직만 비활성화
- **타겟 전환 후에도 여전히 중요**: 언어 장벽 + 정보 비대칭이 있는 외국인 관광객에게 Hidden Gems 가치가 더 큼 — 자금 확보 시 최우선 적용
- **임시 대안**: `includeHiddenGems` → "얼마나 자주 가세요?" (방문 빈도 질문)으로 UX 대체

## 데이터 전략 요약

| 소스 | 역할 | 비용 |
|------|------|------|
| TourAPI | 관광지·맛집·문화시설 배치 적재 | 무료 |
| 카카오 로컬 API | 맛집·카페 배치 적재 + 카테고리 쿼터 미달 시 실시간 보충 | 무료 (월 300,000 트랜잭션) |
| 네이버 지역검색 API | 동네 단위 로컬 맛집 보강 (`collect_naver_local.py`) | 무료 (일 25,000콜) |
| OpenWeatherMap | 날씨 기반 실외/실내 가중치 조정 | 무료 티어 |
| Serper API | 콘서트·이벤트 실시간 검색 + pgvector 캐시(TTL 7일) — **계획** | 유료 (검색당 과금) |
| KOPIS | 클래식·뮤지컬·연극 공연 데이터 — **계획** | 무료 |
| 공공데이터포털 대중교통 API | 이동 시간·요금 계산 | 무료 |

> ✅ **장소 데이터 다국어화 방식 결정 (2026-07-10)**: `places.name`/`address`가 전부 한국어이며 영문 컬럼 자체가 없던 문제. "영문화"로 좁게 잡았던 스코프를 i18n 인프라(한/영/일/중 4개 언어)에 맞춰 **4개 언어 전체**로 재정의. 큐레이션 배치 데이터(21,543건)는 배치 LLM 번역(Haiku, 관광지·역·주요 시설부터 단계적 적용), 사용자가 카카오 검색으로 직접 추가하는 신규 장소는 첫 조회 시 실시간 번역 후 DB에 write-through 캐시하는 하이브리드 방식. 스키마는 `name_en`/`name_ja`/`name_zh_hans`/`name_zh_hant`, `address_en`/`address_ja`/`address_zh_hans`/`address_zh_hant` 개별 컬럼. 기존에 있던 "해외 장소 DB(OpenStreetMap/Google Places)" 전략은 **한국인이 해외로 나가는(아웃바운드) 시나리오** 전제였으므로 이번 타겟 전환(외국인이 한국에 오는 인바운드)과 맞지 않아 폐기.
